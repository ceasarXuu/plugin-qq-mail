# 本地 MCP 插件的构建和模拟验证

已在本项目实践验证的开发约定：

1. 先运行 `npm run check`。邮件库使用随已安装版本发布的类型声明，避免照搬旧版深层文件路径。
2. 运行 `npm test`。测试使用 `node --import tsx --test`，不使用 `tsx` CLI；后者会创建额外 IPC 监听，在当前 Codex 沙箱中曾因 `listen EPERM` 失败。Node 测试运行器加 tsx 导入已通过验证。
3. 测试中的邮箱和 SMTP 为内存替身；独立 stdio 验证强制使用临时目录下不存在的配置路径，只检查启动、工具发现和缺失配置响应。不要继承真实邮箱配置。
4. `npm run build` 将服务器和配置工具各自打包为 CJS，并检查仅外部引用 Node 内置模块；发布包运行时不依赖 node_modules。构建同时保留运行时依赖的许可文本。
5. `npm run package` 后检查压缩包里的根清单、隐藏兼容文件及构建入口。源码或文档改变后重新打包。禁止把本机授权码、配置、发送状态或依赖目录放入包内。

移动邮件必须先检查服务器 `MOVE` 或 `UIDPLUS` 能力。已安装的 ImapFlow 在没有 MOVE 时回退到 COPY、标记删除和 EXPUNGE；缺少 UIDPLUS 时 EXPUNGE 可能清理其他已标记删除的邮件。本项目在这类服务器上拒绝移动，相关模拟测试已验证不会继续操作。
